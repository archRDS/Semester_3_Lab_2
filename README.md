## Связь с первой лабораторной

В папки `c++` и `go` скопированы исходники первой лабораторной. Стек используется в RPN, динамический массив — при перечислении подмножеств, двусвязный список — в LFU. C++ проверка дерева использует `AvlNode` и `AvlTree` из `value3.h`; вставка специально выполняется без поворотов, иначе проверка сбалансированности всегда возвращала бы YES. В Go дерева в исходной лабораторной не было, поэтому добавлены соответствующие узлы и операции. Множество и оба метода хеширования реализованы самостоятельно; задачи 3 и 6.2 используют эти реализации.

Для Хаффмана узел `AvlNode` дополнен весом и данными символа; алгоритм использует те же связи двоичного дерева. В Go проверка сбалансированности и Хаффман также используют общий тип узла.

C++ программа второй лабораторной находится в `c++/lab2.cpp`, первая программа сохранена в `c++/main.cpp`. Это две разные точки входа: собирать их вместе нельзя. В Go к прежней точке входа добавлен режим `lab2`; старые команды первой лабораторной продолжают работать без этого слова.

## Сборка

C++17, GCC или Clang, из папки `c++`:


Go 1.20 или новее, из папки `go`:

```sh
go build -o ../lab2-go .
```

Далее примеры приведены для C++. Для Go замените `./lab2-cpp` на `./lab2-go lab2`.

## Запуск заданий

### 1. Обратная польская запись

```sh
./lab2-cpp rpn "3 1 4 * +"
# 7
```

Поддерживаются беззнаковые `uint64_t` и операции `+`, `-`, `*`. Для многозначных чисел нужны пробелы. Компактная форма `314*+` трактуется как выражение с однозначными операндами. Вычитание, которое дало бы отрицательное число, и переполнение приводят к сообщению `error` и ненулевому коду завершения.

### 2. Множество

```sh
./lab2-cpp --file sets.txt --query "SETADD colors red"
./lab2-cpp --file sets.txt --query "SET_AT colors red"
./lab2-cpp --file sets.txt --query "SETDEL colors red"
```

Синтаксис: `операция имя_множества значение`. Имена и значения не содержат пробелов. Ответ `TRUE` означает успешное добавление, удаление или наличие элемента; повторное добавление и удаление отсутствующего элемента возвращают `FALSE`. Файл создаётся при первом добавлении; обе программы читают один формат `LAB2SETS`. Он отличается от формата базы первой лабораторной: используйте отдельный файл.

### 3. Разбиение множества

```sh
./lab2-cpp partition 15 4 10 5 1 3 7
./lab2-cpp partition 10 4 10 5 1 3 7
```

Первое число задаёт сумму каждого подмножества, остальные — натуральные элементы множества. Повторяющиеся числа удаляются через множество задания 2. Выводится одно подходящее разбиение; оно может отличаться от примера ТЗ. Если разбиения нет, программа сообщает `partition impossible`.

### 4. Все различные подмножества массива

```sh
./lab2-cpp subsets x y z
```

По примеру ТЗ перечисляются все выборки элементов, включая пустую и несмежные элементы. Значения предварительно сортируются для устранения повторных результатов. Кратность элементов сохраняется: для `x x` выводятся `{}`, `{x}`, `{x x}`. Порядок строк несущественен.

### 5. Проверка дерева

```sh
./lab2-cpp balanced 7 3 2 1 9 5 4 6 8 0
# YES
./lab2-cpp balanced 1 2 3 0
# NO
```

Строится обычное бинарное дерево поиска по порядку вставки. Повторяющиеся ключи пропускаются, ноль завершает последовательность и в дерево не включается. Проверяется разность высот у каждой вершины. Пустое дерево сбалансировано.

### 5*. Хаффман

```sh
$archive=$(./lab2-cpp huffman encode "abracadabra")
./lab2-cpp huffman decode "$archive"
# abracadabra
```

Результат кодирования — самостоятельный текстовый архив `HEX:частота,...|биты`. До `|` хранится таблица частот байтов, после — бинарный код. Декодер восстанавливает такое же дерево по частотам и детерминированному правилу разрешения равных весов. Исходный текст для декодирования не нужен. UTF-8, пробелы, пустая строка и строка из одного символа поддерживаются. Архивы совместимы между C++ и Go. Кодирование выполняется по байтам UTF-8; после декодирования восстанавливаются исходные байты.

### 6.1. Хеш-таблицы

```sh
printf 'SET a 10\nSET b 20\nGET a\nDEL b\nGET b\nSTATS\n' | ./lab2-cpp hash chain
printf 'SET a 10\nGET a\n' | ./lab2-cpp hash cuckoo
./lab2-cpp benchmark 100000
```

Команды читаются построчно со стандартного ввода до его конца. `SET key value` добавляет или обновляет пару, `GET key` возвращает значение либо `-1`, `DEL key` возвращает `TRUE/FALSE`, `STATS` показывает число элементов и ячеек. Для этих сеансов файл не используется.

При цепочках каждый индекс содержит последовательность пар. Заполнение свыше 90% вызывает увеличение таблицы и повторное хеширование. При хешировании кукушки используются две таблицы и две хеш-функции. Ключ занимает одну из двух возможных ячеек; занятый ключ вытесняется в другую таблицу. При цикле выполняется перестроение с новым seed и большей ёмкостью. Общая загрузка поддерживается не выше 50%.

Цепочки проще, допускают высокую загрузку и обычно быстрее вставляют элементы, но поиск зависит от длины цепочки. Кукушка проверяет не больше двух ячеек при поиске и удалении; за это платит дополнительной памятью, вытеснениями и дорогим перестроением при циклах. В обоих методах рост таблицы делает вставку амортизированной операцией.

### 6.2. Изоморфные строки

```sh
./lab2-cpp isomorphic fall redd
# YES
./lab2-cpp isomorphic mad odd
# NO
```

Проверяется взаимно однозначное соответствие символов в обоих направлениях. Прямое соответствие хранится в таблице цепочек, обратное — в таблице кукушки. Поддерживаются символы UTF-8.

### 7. LFU

```sh
printf 'SET 1 10\nSET 2 20\nGET 1\nGET 1\nGET 2\nSET 3 30\nGET 2\n' | ./lab2-cpp lfu 2
# 10, 10, 20, -1 (каждый ответ на отдельной строке)
```

Ёмкость задаётся при создании кэша. Частота новой записи равна 1; успешный GET и SET существующего ключа увеличивают частоту. Неуспешный GET возвращает `-1` и частоту не меняет. При равенстве частот удаляется запись, к которой обращались раньше остальных (LRU среди равных). Ёмкость 0 поддерживается. SET ничего не печатает, GET возвращает значение по ключу согласно примерам ТЗ.

## Сложность

| Алгоритм | Время | Дополнительная память |
|---|---|---|
| RPN | O(n) | O(n) |
| Множество в памяти | ожидаемо O(1), вставка амортизированно | O(n) |
| Разбиение на k групп | до O(k^n), перебор с отсечениями | O(n+k) без рекурсивных вспомогательных множеств |
| Подмножества | O(n·2^n) в худшем случае | O(n·2^n) с результатами |
| Построение обычного BST | до O(n²) | O(n) |
| Проверка сбалансированности | O(n) | O(n) |
| Хаффман | O(n + a log a), a ≤ 256 | O(n+a), включая результат |
| Цепочки | ожидаемо O(1), худшее O(n) | O(n) |
| Кукушка, поиск/удаление | O(1), две ячейки | O(n) |
| Изоморфизм | ожидаемо O(n) | O(a) |
| LFU в этой реализации | O(capacity) на поиск/обновление порядка и вытеснение | O(capacity) |

Чтение и сохранение файла множества занимает O(n) дополнительно к операции в памяти; требование O(1) относится к операции АТД, а не ко всему запуску программы с дисковым вводом-выводом. Разбиение множества и полный вывод подмножеств предназначены для небольших входных наборов из-за собственной сложности задач.

## Эмпирический анализ хеширования

Измерено 03.11.2026: C++17 через Clang 0.13.0 с `-O2`, Go 1.23.2. Один прогон каждой команды, время в микросекундах. Ключи `key0...key(N-1)`, значения — номера. Измеряется суммарная вставка (включая рост) и успешный поиск всех N ключей. Время включает преобразование номеров в строки. Это локальное измерение, а не универсальное ранжирование методов.

| Язык | N | Метод | Вставка, мкс | Поиск, мкс | Ячеек |
|---|---:|---|---:|---:|---:|
| C++ | 10 000 | цепочки | 2477 | 545 | 12287 |
| C++ | 10 000 | кукушка | 2611 | 567 | 24574 |
| C++ | 100 000 | цепочки | 53980 | 18457 | 196607 |
| C++ | 100 000 | кукушка | 61296 | 17019 | 393214 |
| Go | 10 000 | цепочки | 2294 | 1097 | 12287 |
| Go | 10 000 | кукушка | 3836 | 518 | 24574 |
| Go | 100 000 | цепочки | 65494 | 22157 | 196607 |
| Go | 100 000 | кукушка | 81364 | 15475 | 393214 |

В этих прогонах цепочки быстрее вставляли элементы и использовали меньше ячеек. При N=100000 кукушка быстрее искала существующие ключи в обеих реализациях. Отдельные короткие измерения могут заметно колебаться; для повторения используйте команду `benchmark`.

## Проверки

```sh
python3 verify.py ./lab2-cpp ./lab2-go
```

Проверяются примеры, ошибочная RPN, отрицательный результат вычитания и переполнение, невозможное разбиение, повторы массива, пустое и несбалансированное дерево, Хаффман для пустой строки и одного символа, биекция изоморфизма, 6000 операций каждого метода хеширования на каждом языке, случайные LFU-сеансы при ёмкостях 0/1/3. Также проверяются общие файлы множества и архивы Хаффмана между языками. UTF-8 текст кодируется по байтам, архив сохраняет исходные байты.
